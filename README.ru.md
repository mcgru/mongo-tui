# mongo-tui

Терминальный клиент MongoDB: слева дерево объектов, справа MQL/JSON-редактор,
сетка результатов и просмотр документа, сохранённые профили подключений и
контекстное автодополнение.

До 2026-11-14 продукт назывался `psql-tui`. PostgreSQL-адаптер удалён после
аудита паритета M6; в репозитории остались только архитектурные документы.

**Статус: pre-alpha, M0–M6 закрыты.** Готовы Mongo-workbench, каталог, дерево,
карточки коллекций, MQL-парсер, автодополнение, шаблоны, переименование с
миграцией config/state и удаление PostgreSQL-пути.

## Зачем

`mongosh` — хороший REPL, но всё ещё консоль: нет дерева объектов, нет
контекстных подсказок, pretty-printed вывод приходится читать, а не
просматривать. `mongo-tui` работает через официальный Go-драйвер: результаты —
типизированные BSON-документы, курсоры стримятся, транзакции — driver sessions,
а интерфейс даёт нормальную сетку, карточку объекта и просмотр документа.

Свой протокол MongoDB `mongo-tui` не реализует и `mongosh` дочерним процессом не
запускает. Один клиент драйвера видит все базы, поэтому переключение текущей базы
локально и не сбрасывает открытую транзакцию.

## Требования

- MongoDB 8.0 или новее; для транзакций нужен replica set
- Go 1.25+ для сборки из исходников
- Linux; macOS и Windows — отдельное решение

## Сборка и запуск

```sh
make                 # список целей
make build           # bin/mongo-tui
make run ARGS=--help
make test
```

## Быстрый старт

```sh
./bin/mongo-tui 'mongodb://ann@127.0.0.1:27017/app?replicaSet=rs0'
./bin/mongo-tui --profile mongo-prod
./bin/mongo-tui                      # выбор подключения
```

Пароль спрашивается в TUI и не попадает ни в конфиг, ни в state, ни в командную
строку. URI MongoDB нельзя комбинировать с `--profile`. Read-only режим
включается `--read-only`.

На экране выбора `i` импортирует MongoDB URI из файла `~/.mongo*`, например
`.mongorc.js` или истории mongosh. Показывается список подходящих обычных
файлов; пароли вырезаются из сохранённого URI, дубликаты пропускаются, а путь
к файлу-источнику запоминается в профиле. При открытии такого профиля пароль
перечитывается из этого файла — как `.pgpass`, — и повторно не спрашивается;
если файла нет или он больше не совпадает, TUI снова запрашивает пароль.

## Редактор

Редактор принимает один запрос за запуск: JSON-envelope или ограниченную
MQL-команду. Обе формы компилируются в один внутренний query spec. Примеры:

```json
{"op":"find","collection":"users","filter":{"age":{"$gt":30}},"sort":{"name":1},"limit":100}
```

```js
db.users.find({age: {$gt: 30}}).sort({name: 1}).limit(100)
db.orders.aggregate([{$match: {status: "paid"}}, {$group: {_id: "$customer", n: {$sum: 1}}}])
db.users.insertOne({name: "Ann", when: ISODate("2026-11-14T12:00:00Z")})
```

Поддержаны операции: `find`, `aggregate`, `count`, `distinct`, `insertOne`,
`insertMany`, `updateOne`, `updateMany`, `replaceOne`, `deleteOne`,
`deleteMany`, `createCollection`, `dropCollection`, `createIndex`,
`dropIndex`, `collMod`, `renameCollection`, `beginTransaction`,
`commitTransaction`, `abortTransaction`.

MQL покрывает CRUD/DDL-подмножество выше, цепочку `find` (`sort`, `project`,
`skip`, `limit`), JSON5-подобные объекты, `ObjectId`, `ISODate`,
`NumberDecimal`, `NumberLong`, комментарии, `db["name"]` и
`db.getCollection("name")`. Транзакции и views пока через JSON-envelope. MQL
намеренно не JavaScript: без переменных, циклов, пользовательских функций и
произвольного кода.

`update`, `replace` и `delete` требуют явный `filter` (`{}` — для всех
документов). TUI разбирает запрос до отправки, поэтому неполный envelope или
MQL не уходит на сервер.

## Дерево объектов

Дерево показывает базы, коллекции, views, индексы, пользователей и роли.
`Enter` на базе переключает сессию; `Enter` на коллекции открывает карточку с
полями по выборке, индексами, статистикой, options и JSON Schema validator.
`F5` перезагружает ветку. Текущая база отмечена в дереве и в заголовке.

`+` на папке **Databases** заготовка новой базы: спрашивает имя, делает
клиентский `use`, чтобы писать в неё можно было сразу, и показывает её
блёкло-розовой. MongoDB создаёт базу только когда в неё записан документ, поэтому
заготовленная база становится настоящей и текущей (зелёной), как только появляется
в `listDatabases`; уход на другую базу до записи убирает заготовку.

Карточка отличает поля из выборки от ключей индексов и свойств validator и
показывает статистику коллекции. Поля — это выборка, а не схема.

`Ctrl+Space` подсказывает базы, коллекции, методы, поля, операторы
query/update, стадии агрегации и значения JSON. `/` вставляет find, `p`
запускает ограниченный find, `+` на базе или её папке **Collections** вставляет
готовый новый документ `insertOne` (создаёт коллекцию первой записью, `createdAt`
заполнен, курсор на имени), `+` на коллекции вставляет `createIndex`, `+` на
папке **Users** импортирует пользователя (то же, что `i`), `-` — drop или
dropIndex, `=` — collMod; `.` вставляет имя коллекции JSON-строкой.

`Enter` (или `→`) на строке **Users** открывает пользователя в OBJECT-панели:
его домашнюю базу и аутентификацию, затем чеклист ролей. `↑↓` — переход,
`Space` — переключить выдачу (существующие роли можно снять, неиспользованные
builtin-добавить на домашнюю базу пользователя), `Enter` — сохранить через
`updateUser` (пароль не трогается), `Esc` — закрыть без сохранения.

`i` на папке **Users** импортирует пользователя MongoDB из файла `~/.mongo*`:
из выбранного URI берутся имя пользователя, пароль, база и `authSource`. Затем
чеклист выбирает, какие builtin-роли базы выдать (`read`, `readWrite`, `dbOwner`,
`dbAdmin`, `userAdmin`; пробел — отметить, Enter — применить, `readWrite`
отмечен по умолчанию); роли выдаются на базу из URI, а если её нет — на текущую
выбранную. Если в файле несколько URI, показывается второй список для выбора.
Пользователь создаётся или обновляется с выбранными ролями. Пароль уходит
напрямую в `createUser`/`updateUser` и в state не пишется.

## Клавиши и раскладка

```
┌ mongo-tui | db:app | user: ann | MongoDB 8.0 | CONNECTED ┐
├──────────────────────┬───────────────────────────────────┤
│ MONGODB              │ [RESULT] [OBJECT] [MESSAGES]      │
│ ▾ Databases          ├───────────────────────────────────┤
│   ▸ app              │ ...                               │
│ ▾ Users              │                                   │
│ ▾ Roles              │                                   │
│                      ├───────────────────────────────────┤
│                      │ MQL / JSON EDITOR                 │
└──────────────────────┴───────────────────────────────────┘
```

- `Ctrl+J` — выполнить запрос под курсором или выделение (`Ctrl+A` выделяет
  весь буфер), `Ctrl+R` — история, `Ctrl+Space` — подсказки.
- `Ctrl+F1` — справка; F1 тоже привязан, но Konsole может его забирать.
- `Tab`/`Shift+Tab` — фокус; `]`/`[` — вкладки RESULT/OBJECT/MESSAGES.
- `Ctrl+←/→` — ширина дерева; `Ctrl+↑/↓` — разделитель результата и редактора.
- `c` — копировать ячейку, `C` — строку как TSV через OSC 52.
- `/`, `p`, `+`, `-`, `=` — шаблоны MongoDB; `.` — вставить имя.
- `Ctrl+Q` — выход; `Ctrl+C` — отменить запрос, затем выйти.

Все команды переназначаются в `[keys]`; справка показывает фактические привязки.

## Транзакции, отмена, read-only

- Транзакции идут через driver sessions и требуют replica set. На standalone
  сервере UI сообщает, что транзакции недоступны.
- Отмена — `killOp` с уникальным comment у запроса; код 11601 показывается как
  «запрос отменён». Нужна привилегия `killop`; без неё UI честно говорит, что
  отмена недоступна. Отмена Go-контекста сама по себе закрывает соединение и
  оставляет серверную операцию работать, поэтому как пользовательская отмена не
  используется.
- Read-only режим отклоняет write-envelope на клиенте. Это не граница
  безопасности БД; используйте пользователя с ролью только на чтение.

## Конфигурация и миграция

Конфиг — `$XDG_CONFIG_HOME/mongo-tui/config.toml` (обычно
`~/.config/mongo-tui/config.toml`). Профили и история подключений — в
`$XDG_STATE_HOME/mongo-tui/state.json`; пароль туда не пишется.

При первом запуске после переименования старые `psql-tui` config/state
копируются в новые пути. Новые файлы никогда не перезаписываются, старые
остаются на месте, рядом с каждым мигрированным файлом появляется копия
`.psql-tui.bak`. Старые PostgreSQL-профили сохраняются как legacy-данные; после
M6 подключиться по ним нельзя, но и молча они не удаляются.

```toml
read_only = false
result_limit_rows = 10000
result_limit_bytes = 33554432

mouse = false

[mongodb]
sample_size = 50

[keys]
run = "ctrl+j"
history = "ctrl+r"
select_template = "/"
```

При первом запуске файл создаётся со всеми настройками закомментированными.
Неизвестное действие, пустая клавиша или две команды на одной клавише — ошибка
при запуске. Стрелки, Home/End, PgUp/PgDn, Enter/Space и Esc фиксированы.

## Тесты

```sh
make test          # юнит-тесты; живые сами пропускаются без DSN
make test-mongo    # MongoDB 8.0 replica set, живые тесты адаптера и TUI
make test-mongo-auth # живые SCRAM/TLS/authSource тесты на standalone
make mongo-down
make auth-down
```

Живые Mongo-тесты создают и удаляют уникальные коллекции.
