# Spike: MongoDB как движок mongo-tui

Дата: 2026-11-14. Статус: завершён, решение по движку подтверждено (ADR 0006).

## Окружение

- Сервер: MongoDB 8.0.38, образ `mongo:8.0`, один узел в режиме replica set
  `rs0`, `127.0.0.1:57017`.
- Клиент: Go 1.26.0, официальный драйвер `go.mongodb.org/mongo-driver/v2`
  v2.10.0. `mongosh` как движок не использовался.
- Проба: отдельная программа в `/tmp/msh-tui/spike-mongo/probe`, отчёт
  `/tmp/msh-tui/spike-mongo/report.json`.
- Порт 27017 не занят пробой: там локальный mongod пользователя, его не трогали.

Воспроизведение:

```sh
bash /tmp/msh-tui/spike-mongo/up.sh
cd /tmp/msh-tui/spike-mongo/probe
MONGO_URI='mongodb://127.0.0.1:57017/?replicaSet=rs0' go run .
```

`up.sh` поднимает `mongo:8.0` с `--replSet rs0`, инициирует набор и ждёт
primary. Проба сама создаёт базу `spike`, фикстуры, 100 тыс. документов для
sampling и большую строку на 5 МиБ.

## Вердикт

Официальный Go-драйвер годится как единственный движок. Переносить архитектуру
«живой psql + CSV + маркер» на MongoDB нельзя: `mongosh` — это Node.js REPL с
pretty-printed выводом и без надёжной границы запроса, а разовый `--eval`
теряет транзакции и курсоры. Драйвер даёт типизированные BSON-документы,
курсоры, сессии и контекст — этого достаточно для workbench, каталога и
транзакций.

Гибридный редактор подтверждён: документы раскладываются в сетку, вложенность,
массивы и BSON-типы читаются, полный документ можно показать отдельно.

Отмена требует `killOp`. Отмена через `context` не является отменой: она рвёт
соединение, возвращает транспортную ошибку, а серверная операция продолжает
работать. Это главный вывод спайка.

## Что важно

### Context-отмена — не отмена

Замер: запрос запущен, через 300 мс отменён контекст. Клиент вернул
`connection(...) incomplete read of message header: context canceled`, а
операция на сервере осталась в `$currentOp` и продолжала выполняться. Только
`killOp` по `opid` её прервал. Поэтому в продукте отмена — это:

1. уникальный `comment` у запроса;
2. поиск `opid` в `$currentOp` по этому comment;
3. `killOp`;
4. код 11601 показывается как «запрос отменён», а не как сбой.

### killOp требует права

`killOp` выполняется под тем же пользователем и требует привилегии `killop`.
Если её нет, UI должен честно сказать, что отмена недоступна. Закрыть
соединение — не замена: серверная операция может продолжить работу, а
пользователь решит, что запрос остановлен. Права непривилегированного
пользователя в этом спайке не проверялись — это отдельный пункт чек-листа.

### BSON → сетка

Правила, проверенные на фикстуре:

- колонки — объединение ключей в батче, `_id` первым;
- вложенные объекты — точки до заданной глубины (в пробе — 2), глубже — EJSON;
- массивы и объекты на листе — compact relaxed EJSON;
- пропуск, null и пустая строка — три разных состояния;
- ObjectID, Decimal128 и дата рендерятся человекочитаемо, без потери значения;
- при смешанных типах колонка помечается mixed, а не приводится к строке
  молча.

### Схемы нет

Поля коллекции — это наблюдение, а не схема. Карточка должна показывать, по
какой выборке собраны поля, и учитывать JSON Schema validator и ключи
индексов. Выборка 50 документов из 100 тыс. заняла 16–30 мс; кэш с TTL
обязателен, иначе каждый вход в коллекцию будет платить эту цену.

### Транзакции только на replica set

На одиночном `mongod` без replica set транзакции недоступны. Это не ошибка
подключения, а ограничение режима; UI должен показывать его явно. Проверка —
`hello.setName` непустой.

### Предел документа

16 МиБ на BSON-документ. Документ на 5 МиБ занимает 5,24 МБ в relaxed EJSON.
Сетка не должна рендерить такое в ячейку целиком: нужен лимит байт на ячейку и
полный просмотр во вкладке OBJECT.

### Чего нет в MongoDB

Нет схем, tablespaces, sequences, пользовательских типов и владельца
коллекции. Нет `SET ROLE`, `search_path` и `default_tablespace`. Нет
`pgpass`, `COPY`, `\gdesc` и command-tag. Роль — это пользователь кластера;
смена identity означает новый клиент, а не `SET ROLE`. Всё это вычеркивается
из продуктовой модели, а не эмулируется.

## Контракт после spike

- Подключение: `mongodb://` или `mongodb+srv://`; пароль спрашивается в TUI и
  не попадает в argv, конфиг и state. URI с паролем отвергается.
- Запрос: JSON-envelope и ограниченный MQL-текст компилируются в один
  `query.Spec`; произвольный JavaScript не исполняется.
- Исполнение: курсор, батчи, лимит документов и байт, статус усечения.
- Отмена: comment → `$currentOp` → `killOp`; код 11601 = отменено.
- Транзакции: driver session; replica set обязателен; на standalone режим
  недоступен.
- Read-only: клиентский запрет write-операций плюс пользователь с правами
  только на чтение; это не security boundary.
- Результат: flatten в сетку, полный EJSON в OBJECT.
- Каталог: `listDatabases`, `listCollections`, `listIndexes`, `usersInfo`,
  `rolesInfo`, `buildInfo`, `hello`, `$collStats`.
- Пределы: 16 МиБ BSON, лимит ячейки, лимит результата.

## Что осталось непроверенным

- Аутентификация: SCRAM, x509, LDAP; `authSource`; поведение при неверном
  пароле.
- TLS и `mongodb+srv://` (DNS SRV).
- Sharded cluster и транзакции на нём.
- `killOp` под непривилегированным пользователем: какая именно привилегия
  нужна и как выглядит отказ.
- Сетевой обрыв без закрытия сокета и поведение пула после него.
- Change streams, explain plan, time-series коллекции, pipelines во views.
- Стоимость sampling на холодном кэше и на коллекциях в сотни миллионов
  документов.
- Документы, близкие к 16 МиБ, и результаты в сотни тысяч документов.
