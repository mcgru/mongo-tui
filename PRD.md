# mongo-tui — PRD

Статус: M0–M6 закрыты 2026-11-14. PostgreSQL-путь удалён после аудита
паритета; продукт работает только с MongoDB.

Решение: PostgreSQL заменён на MongoDB целиком. Целевой продукт —
`mongo-tui`; psql-путь удалён в M6. Прежний PRD описывал psql-tui и заменён
этим документом.

Источники:
- `docs/adr/0006-mongodb-as-engine.md` — решение о движке и отмене;
- `docs/mongo-parity.md` — аудит паритета и список post-M6 hardening;
- `docs/spike-mongo.md` — измеренное поведение MongoDB 8.0;
- `docs/dialogue-log.md` — ход согласования;
- `docs/spike-psql-protocol.md` — старый spike psql, исторический.

## 1. Что делаем

`mongo-tui` — полноэкранный терминальный клиент MongoDB. Своего протокола не
реализует и `mongosh` дочерним процессом не запускает: работает через
официальный Go-драйвер, держит один клиент на все базы и отвечает за интерфейс
— дерево объектов, MQL/JSON-редактор, сетку результатов, просмотр документа,
историю подключений и автодополнение.

Ценность: подключиться без повторного ввода параметров, увидеть базы,
коллекции и индексы без `show dbs`/`show collections`, написать запрос с
подсказками, выполнить его и получить управляемую таблицу документов, не
покидая терминал.

## 2. Границы

Входит: URI и профили, пароль в TUI без хранения, read-only режим, одна
активная сессия, дерево Databases → Collections/Views → Indexes + Users/Roles,
карточка коллекции и пользователя (роли редактируются во вкладке OBJECT),
MQL/JSON-редактор, выполнение одного запроса за запуск,
сетка BSON-документов, полный документ во вкладке OBJECT, сообщения, отмена
через `killOp`, транзакции на replica set, автодополнение, MQL-шаблоны, история
запросов в сессии, переназначаемые клавиши, миграция старых config/state.

Не входит: свой wire protocol, `mongosh` как движок, произвольный JavaScript,
SQL-эмуляция, Atlas SQL/BI Connector, администрирование кластера (репликация,
failover, шардирование), визуальный конструктор, ER-диаграммы, экспорт/импорт,
несколько кластеров одновременно.


## 3. Принятые решения

| Решение | Значение |
|---|---|
| Имя продукта и бинаря | `mongo-tui`; модуль `mongo-tui`, команда `cmd/mongo-tui`, XDG-пути `mongo-tui` |
| Язык и TUI | Go 1.25+, `charmbracelet/bubbletea` + `bubbles` + `lipgloss` |
| Движок | MongoDB 8.0+, официальный `go.mongodb.org/mongo-driver/v2`; без `mongosh` |
| Подключение | `mongodb://`/`mongodb+srv://` URI и профили; пароль только в TUI |
| Язык запросов | JSON-envelope — канон; ограниченный MQL компилируется в тот же `query.Spec` |
| Клиент и базы | один клиент на все базы; текущая база — состояние UI, переключение без переподключения |
| Дерево | Databases → Collections/Views → Indexes; Users и Roles на уровне кластера |
| Карточка | sample полей + ключи индексов + свойства validator + stats + options |
| Локальное состояние | TOML-конфиг + JSON state; старый `psql-tui` мигрируется с `.psql-tui.bak` |
| Секреты | пароль MongoDB не хранится; config/state не содержат секретов |
| Язык UI | английский; README.md первичен, README.ru.md синхронно |
| Платформа MVP | Linux; macOS/Windows — отдельное решение |
| Версии | MongoDB 8.0+ |

## 4. Поведение продукта

### 4.1 Подключение

- Запуск без параметров — выбор из профилей; `mongodb://`/`mongodb+srv://`
  подключаются сразу; `--profile NAME` выбирает сохранённый профиль.
- `mongo-tui` принимает только URI или профиль; Mongo URI нельзя комбинировать
  с `--profile`.
- Пароль спрашивается в TUI, не попадает в argv, конфиг, state, историю и
  логи. URI с паролем отвергается.
- На экране выбора `i` открывает список обычных файлов `~/.mongo*` и
  импортирует найденные MongoDB URI из `.mongorc.js`, истории mongosh/mongo и
  похожих файлов. Пароли из URI вырезаются, дубликаты пропускаются, профили
  сохраняются в state вместе с путём к файлу-источнику (`source_file`). При
  подключении такого профиля пароль перечитывается из этого файла, как
  `.pgpass`, и повторно не спрашивается; файла нет или URI больше не совпадает
  — TUI снова запрашивает пароль.
- Read-only включается `--read-only`; write-операции и агрегации с
  `$out`/`$merge` отклоняются на клиенте. Это не замена серверным ролям.
- Потеря соединения и ошибки аутентификации показываются пользователю;
  неверный пароль не приводит к бесконечному повторному запросу.

### 4.2 Дерево и карточка

- Ленивое дерево: `Databases`, `Users`, `Roles`; внутри базы — `Collections`
  и `Views`; внутри коллекции — `Indexes`. Ошибка прав видна в узле; `F5`
  перезагружает ветку. Запись, меняющая список коллекций (`insertOne`/`insertMany`,
  upsert-обновление, `createCollection`, `dropCollection`, `renameCollection`), после
  успеха сама перезагружает папку `Collections` затронутой базы и наводит курсор на
  новую коллекцию — без `F5` и без перелогина (раньше коллекция появлялась только
  после перелогина).
- `Enter` на базе переключает текущую базу; `Enter` на коллекции открывает
  карточку; стрелка вправо раскрывает индексы; `Enter` на индексе показывает
  его ключи.
- `Enter` (или `→`) на пользователе открывает его карточку во вкладке OBJECT:
  домашняя база (`db`), механизмы аутентификации и на первом месте — чеклист
  ролей. `↑↓` переводят курсор, `Space` переключает выдачу: существующую роль
  можно снять, неиспользованную builtin-роль базы (`read`, `readWrite`, `dbOwner`,
  `dbAdmin`, `userAdmin`) добавить на домашнюю базу пользователя. `Enter` сохраняет
  через `updateUser` (пароль не меняется) и перечитывает карточку; `Esc` закрывает
  без сохранения. Карточка коллекции и пользователя во вкладке взаимоисключающи.
- Текущая база отмечена в дереве и в заголовке. После подключения и
  переключения папка Databases раскрывается автоматически.
- `+` на папке Databases заготавливает новую базу: спрашивает имя, делает
  клиентский `use` (`SwitchDatabase`, без обращения к серверу) и показывает узел
  блёкло-розовым (provisional). MongoDB создаёт базу только при записи документа,
  поэтому provisional остаётся до первой записи: после успешной записи дерево
  Databases перезагружается, и когда `listDatabases` начинает показывать базу,
  розовая отметка снимается и она рендерится как текущая (зелёным). Переход на
  другую базу до записи убирает provisional. Имена с запрещёнными MongoDB
  символами (`. $ / \ " *` и пробелы) отвергаются на клиенте; сервер — источник
  истины.
- `+` работает и на папках: на **Collections** базы вставляет тот же шаблон
  нового документа `insertOne`, что и на leaf-узле базы (если это не текущая
  база — подсказка «switch to … first»); на **Users** открывает импорт
  пользователя из `~/.mongo*` — то же, что `i`. Раньше на этих узлах `+` молчал.
- Карточка коллекции/вида: тип, поля по выборке (`FIELDS (sample N docs)`),
  индексы, статистика (`collStats`), options и JSON Schema validator. Поля из
  выборки, ключей индексов и свойств validator различаются. Ошибка выборки или
  статистики не скрывает остальную карточку.
- Схем, tablespaces, sequences, пользовательских типов и владельца коллекции
  в MongoDB нет; соответствующие узлы и бейджи отсутствуют.
- Roles собираются по всем базам; builtin-роли — из admin. Users — через
  `usersInfo` с `forAllDBs`.
- `i` на папке Users импортирует пользователя из файла `~/.mongo*`: из
  выбранного URI берутся `user`, `password`, `database` и `authSource`; `database`
  не указан — берётся текущая выбранная база, `authSource` не указан — `admin`.
  Затем чеклист выбирает builtin-роли базы (`read`, `readWrite`, `dbOwner`,
  `dbAdmin`, `userAdmin`; пробел — отметить, Enter — применить, `readWrite`
  отмечен по умолчанию), каждая выдаётся на целевую базу. Несколько URI в файле —
  второй список выбора. Пользователь создаётся/обновляется
  (`createUser`/`updateUser`) с выбранными ролями; пароль в state не пишется.
  После успеха курсор дерева встаёт на пользователя. Модель прав «пока что»
  ограничена базовыми ролями на одну базу и рассчитана на развитие.

### 4.3 Выполнение и вывод

- `Ctrl+J` выполняет запрос под курсором, а при выделении — выделение; несколько
  запросов за запуск — это выделение, разбитое по `;`. Исполненные (✓) строки
  сами по себе не перезапускаются: без выделения берётся только выражение под
  курсором. Mongo-режим отправляет один запрос за запуск: JSON-envelope или MQL.
- Клиентская проверка: `query.ParseRequest` разбирает запрос до отправки;
  неполный JSON/MQL не уходит на сервер. `update`/`replace`/`delete` требуют
  явный `filter`, даже если это `{}`.
- JSON-envelope поддерживает `find`, `aggregate`, `count`, `distinct`,
  `insertOne`, `insertMany`, `updateOne`, `updateMany`, `replaceOne`,
  `deleteOne`, `deleteMany`, `createCollection`, `dropCollection`,
  `createIndex`, `dropIndex`, `collMod`, `renameCollection`,
  `beginTransaction`, `commitTransaction`, `abortTransaction`.
- MQL поддерживает `db.<coll>.<method>(...)` для CRUD/DDL, цепочку find
  (`sort`, `project`, `skip`, `limit`), JSON5-подобные объекты, комментарии,
  `ObjectId`, `ISODate`, `NumberDecimal`, `NumberLong`, `db["name"]` и
  `db.getCollection("name")`. Произвольный JS, переменные и циклы не
  исполняются.
- Результат: документы раскладываются в сетку (объединение ключей, `_id`
  первым, вложенность до двух уровней, массивы и глубже — EJSON, mixed-типы).
  Пропуск, BSON null и пустая строка различаются. Полный EJSON-документ
  открывается во вкладке OBJECT.
- Write/DDL показывают результат команды в MESSAGES; лимиты документов и байт
  дают явный статус усечения. Предел BSON — 16 МиБ.
- История запросов — в памяти сессии, `Ctrl+R`; на диск не пишется.

### 4.4 Транзакции, отмена, read-only

- Транзакции — driver sessions; нужен replica set. Состояние
  `idle`/`in transaction`/`aborted` видно в заголовке. На standalone UI
  сообщает, что транзакции недоступны.
- Отмена — `killOp` по opid из `$currentOp` с уникальным comment. Код 11601
  показывается как «запрос отменён», а не сбой. Нужна привилегия `killop`;
  без неё UI честно говорит, что отмена недоступна. Context-отмена сама по
  себе закрывает соединение и оставляет серверную операцию работать, поэтому
  не используется как пользовательская отмена.
- Read-only — клиентский guard плюс рекомендация пользователя с ролью только
  на чтение; это не граница безопасности БД.

### 4.5 Редактор

- Свой редактор на рунах: выделение, `Shift+стрелки`, `Ctrl+A`, номера строк,
  горизонтальная прокрутка, память колонки.
- Подсветка MQL/JSON: строки, числа, `$`-операторы, методы, стадии,
  комментарии.
- Выполненный запрос приглушён, помечен ✓/✗ и заблокирован; `Ctrl+E`
  размораживает, `Ctrl+K` удаляет. После запуска курсор переходит на новую
  строку.
- MQL-шаблоны: `/` — find, `p` — ограниченный find, `+` — новый документ
  `db.<коллекция>.insertOne({createdAt: ISODate("<текущее UTC>")})` на базе
  (создаёт коллекцию первой записью, `createdAt` заполнен, `_id` не указывается —
  его назначит сервер) и `createIndex` на коллекции, `-` — drop/dropIndex, `=` —
  collMod; после вставки курсор встаёт сразу после имени.
- `.`/`>` вставляют имя коллекции JSON-строкой, фокус остаётся в дереве.

### 4.6 Автодополнение

- `Ctrl+Space`: контекст `db.` — коллекции; `db.<coll>.` — методы; внутри
  `find`/`update`/`delete` — поля и query/update-операторы; внутри
  `aggregate([` — стадии; внутри значения стадии — поля и query-операторы;
  в JSON — значения `op`, `database`, `collection`.
- Поля берутся из выборки документов, ключей индексов и свойств JSON Schema
  validator. Снимок баз/коллекций грузится при подключении и переключении;
  поля — лениво и кэшируются.
- Подсказки не открываются вне распознанного контекста; `Enter` вне popup
  работает как обычно.

### 4.7 Клавиши и раскладка

- `Tab`/`Shift+Tab` — фокус; `]`/`[` — вкладки RESULT/OBJECT/MESSAGES;
  `Ctrl+←/→` — ширина дерева; `Ctrl+↑/↓` — разделитель результата и
  редактора.
- `Ctrl+J` — выполнить, `Ctrl+R` — история, `Ctrl+Space` — подсказки,
  `Ctrl+F1` — справка (F1 может забирать Konsole), `Ctrl+Q` — выход,
  `Ctrl+C` — отмена запроса/выход.
- `c` — копировать ячейку, `C` — строку как TSV через OSC 52.
- Все команды переназначаются в `[keys]`; справка генерируется из фактического
  keymap. Фиксированы только стрелки, Home/End, PgUp/PgDn, Enter/Space, Esc.
- Мышь выключена по умолчанию (`mouse = false`).

### 4.8 Конфиг, состояние, миграция

- Конфиг: `$XDG_CONFIG_HOME/mongo-tui/config.toml`; state:
  `$XDG_STATE_HOME/mongo-tui/state.json`. Пароль не хранится.
- При первом запуске после переименования старые
  `$XDG_CONFIG_HOME/psql-tui/config.toml` и
  `$XDG_STATE_HOME/psql-tui/state.json` копируются в новые пути. Новые файлы
  не перезаписываются, старые остаются, рядом появляется `.psql-tui.bak`.
- Старые PG-профили (`engine` пустой) сохраняются как legacy-данные; после M6
  подключиться по ним нельзя, но и молча они не удаляются.
- Профиль Mongo хранит `engine = "mongo"` и URI без пароля. Импорт из
  `~/.mongo*` создаёт такие профили, подпись берётся из host/db URI, плюс
  запоминается путь к файлу-источнику (`source_file`) — не секрет, пароль в
  state не пишется, а перечитывается из этого файла при подключении.
- Неизвестные ключи конфига, пустая клавиша или две команды на одной клавише —
  ошибка при запуске.

## 5. Отображение модели данных

| PostgreSQL | MongoDB | Поведение mongo-tui |
|---|---|---|
| Кластер, базы | `listDatabases` | Databases, текущая база отмечена |
| Схемы | нет | узла нет; имя — `db.collection` |
| Таблицы | коллекции | Collections, карточка коллекции |
| Views / matviews | views, `$merge`/`$out` | Views; материализация — вне UI |
| Sequences | нет | узла нет |
| Functions / types | `$function`, BSON-типы | из MVP убраны |
| Роли | users/roles кластера | Users/Roles, без `SET ROLE` |
| Tablespaces | нет | узла нет |
| Колонки | схемы нет | поля по выборке + индексы + validator |
| `SET ROLE`/`search_path` | нет | клиентские настройки чтения отсутствуют |
| Транзакции | driver session | replica set обязателен |
| Read-only | серверного флага сессии нет | клиентский guard + read-only user |
| Passfile | нет | пароль в TUI, не хранится |
| Отмена | context + `killOp` | `killOp` по comment; код 11601 |
| CSV/NULL | BSON | сетка/EJSON, null ≠ missing ≠ empty |
| SQL | MQL/JSON | гибридный редактор |
| 16 МиБ BSON | предел | лимиты ячеек/результата, OBJECT |

## 6. Не-цели

- Произвольный JavaScript и полноценный `mongosh`.
- SQL-совместимость и Atlas SQL/BI Connector.
- Администрирование кластера, репликация, failover, шардирование.
- Визуальный конструктор запросов, ER-диаграммы, экспорт/импорт.
- Несколько кластеров одновременно.

## 7. Приёмка и паритет

`docs/mongo-parity.md` — аудит M6. PostgreSQL-путь удалён: `internal/psql`,
`internal/session`, `internal/catalog`, `internal/sqlparse` и SQL-часть
`internal/completion` больше не существуют, ADR 0001/0002/0005 помечены
superseded.

Критерии M6 выполнены:
- `go test ./...` и `make test-mongo` зелёные;
- живой прогон выполняется от непривилегированного пользователя;
- старые config/state мигрированы, legacy PG-профили не потеряны;
- README EN/RU, PRD и ADR соответствуют `mongo-tui`;
- CI собирает, vet-ит и гоняет unit + живой MongoDB job.

Post-M6 hardening закрыт: живые SCRAM/TLS/authSource тесты, неверный пароль,
read-only пользователь, сетевые ошибки, профили, CUR-03/CUR-04, редактор и
`[mongodb] sample_size`. `killOp` своей операции MongoDB разрешает без
отдельной привилегии, поэтому CAN-04 снят как N/A; ошибки отмены показываются
в UI. Внешними остаются x509, `mongodb+srv` (нужен DNS) и sharded cluster.

## 9. Тесты и окружение

- Юнит-тесты Go на все пакеты.
- `deploy/mongo/docker-compose.yml`: MongoDB 8.0, replica set `rs0`.
- `make test-mongo` поднимает replica set и гоняет `internal/mongo/...` и
  `internal/tui`; живые тесты сами пропускаются без `MONGODB_URI`.
- `make test-mongo-auth` поднимает standalone с auth+TLS и проверяет SCRAM,
  authSource, TLS, неверный пароль и права read-only пользователя.
- CI прогоняет gofmt, vet, build, unit, живой MongoDB job; auth-тесты
  запускаются отдельной целью.

## 10. Дефолты и лимиты

- Лимит документов: 10 000 (`result_limit_rows`); лимит байт: 32 МиБ
  (`result_limit_bytes`); при усечении явный статус.
- Sample полей карточки/автодополнения: 50 документов, настраивается
  `[mongodb] sample_size`.
- Новая сессия read-write; `RW`/`RO` и состояние транзакции в заголовке.
- Read-only — клиентский guard; серверные роли обязательны для реальной
  защиты.
- Мышь выключена; `mouse = true` включает отчёт о мыши.
- История запросов — в памяти; на диск не пишется.
- Версия — из ldflags при сборке, git-тег только на релиз.
- Образец конфига пишется при первом запуске, все ключи закомментированы.

## 11. Риски и открытые вопросы

- `killOp` своей операции MongoDB разрешает без отдельной привилегии; для
  чужих операций нужен `killop`. Ошибка отмены показывается в UI.
- Транзакции и change streams требуют replica set; sharded cluster не
  проверялся.
- SCRAM, authSource и TLS проверены живыми тестами; x509 и `mongodb+srv`
  остаются внешними проверками (SRV требует DNS).
- Schemaless: поля карточки — выборка, а не схема; sampling может не увидеть
  редкие поля.
- MQL — подмножество; расширение синтаксиса должно сохранять `query.Spec` и
  строгую валидацию.
- ОС помимо Linux, хранение истории на диске и экспорт/импорт — открытые
  вопросы.
